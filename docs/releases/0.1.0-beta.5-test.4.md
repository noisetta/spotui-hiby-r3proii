# SpotUI 0.1.0-beta.5-test.4

Checkpoint date: 2026-10-08

SpotUI `0.1.0-beta.5-test.4` is a device-tested development checkpoint for the
HiBy R3 Pro II.

This checkpoint is newer than the currently packaged public tester prerelease,
`0.1.0-beta.2`, but is not itself a reviewed public release bundle. The tag
marks the exact source state used for the validated development build.

## Highlights

### Dedicated SpotUI launcher

- Added a dedicated SpotUI launcher tile to the stock HiBy interface.
- Preserved the existing Qobuz tile and functionality.
- Added SpotUI artwork for both stock HiBy themes.
- Added a dedicated native **Preparing SpotUI...** message for launch requests
  made before the device is ready for the handoff.

### Guarded startup

SpotUI now waits for the stock player and audio hardware to reach a known-safe
state before taking control.

The readiness gate checks:

- minimum system uptime;
- the active `hiby_player` process;
- expected player thread initialization;
- framebuffer ownership;
- required ALSA controls;
- stable mixer state across consecutive checks.

This preserves the audio-safe startup behavior discovered during earlier
device testing while providing immediate feedback when SpotUI is requested
early in a cold boot.

### Return to HiBy without rebooting

Normal SpotUI exit no longer requires rebooting the player.

The handoff now:

1. suspends the existing `hiby_player` process before SpotUI takes control;
2. runs SpotUI while the stock interface remains suspended;
3. shuts down the SpotUI UI, daemon, and playback process on exit;
4. resumes the original `hiby_player` process;
5. re-arms the SpotUI launch broker after a short input-settling delay.

This allows normal use of the stock HiBy interface immediately after leaving
SpotUI.

### Touchscreen isolation

SpotUI now takes an exclusive grab on the touchscreen input device while its UI
is active.

The HiBy R3 Pro II uses the MIPS Linux UAPI value:

```text
EVIOCGRAB = 0x80044590
```

Using the target-correct ioctl prevents touch events made inside SpotUI from
remaining queued for the suspended HiBy interface and being replayed when
`hiby_player` resumes.

Before this change, queued events could occasionally select stock HiBy tiles or
immediately relaunch SpotUI after exit.

### Managed runtime upgrades

The firmware-side provisioner can now safely upgrade an existing SpotUI
runtime when it is recognized as a managed installation.

The provisioner:

- verifies the currently installed runtime before replacing it;
- preserves rollback state while installing the new runtime;
- installs only a matched, verified runtime archive;
- leaves unrelated `/usr/data` contents and private credentials untouched;
- retains safe refusal behavior when an existing installation cannot be
  verified as managed.

## Device validation

The `beta.5-test.4` firmware/runtime pair was tested directly on one HiBy R3
Pro II.

Testing included:

- repeated SpotUI launch and exit cycles;
- repeated direct return to the stock HiBy interface;
- multiple cold reboots;
- playback and audio-output checks;
- early-launch readiness behavior;
- native preparation feedback;
- touchscreen isolation;
- runtime provisioning and managed upgrade behavior;
- verification that Qobuz remains available;
- verification that phantom stock-interface tile selections were no longer
  observed after enabling exclusive touchscreen grabbing;
- verification that unintended immediate SpotUI relaunches were no longer
  observed during the tested cycles.

Approximately 10–15 launch/exit cycles were performed on the final packaged
test.4 build after earlier extended development-cycle testing.

A previously observed intermittent stale-framebuffer return condition could
not be reproduced during the final test.4 validation. No speculative
framebuffer-page workaround has therefore been added.

## Release status

`0.1.0-beta.5-test.4` is a development checkpoint, not a public tester
release.

The latest reviewed and packaged GitHub tester prerelease remains
`0.1.0-beta.2`.

A future public release should be assembled through the repository's
privacy-gated release-bundle workflow and should be tested again as the exact
archive intended for distribution.

## Compatibility

- Tested device: HiBy R3 Pro II
- Firmware base: HiBy Mods v1.5
- Playback engine: librespot-based SpotUI daemon
- Spotify account requirement: Spotify Premium
- Automatic SpotUI takeover after boot: not enabled
- Spotify library like/unlike writes: not supported

Do not install development firmware on another HiBy model. Keep recovery
firmware for the exact device available before modifying or flashing firmware.
